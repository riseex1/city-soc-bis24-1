## Матрица доступа

`R` — чтение, `W` — изменение, `—` — запрещено. Гость направляется на вход в Паспортный стол; после входа недостаточная роль даёт 403. Администратор Keycloak сам по себе не имеет роли `аналитик_soc` и не получает прав района.

| Функция района и маршрут | Гость | Житель | Аналитик SOC | Админ Keycloak без роли SOC |
| --- | :---: | :---: | :---: | :---: |
| Смотреть тревоги — `GET /` | — | — | R, все | — |
| Закрыть тревогу — `POST /alerts/<id>/close` | — | — | W, все | — |
| Смотреть и фильтровать журналы — `GET /logs` | — | — | R, все | — |
| Создать сообщение — `POST /reports` **(новое)** | — | W, своё | — | — |
| Смотреть список своих сообщений — `GET /reports` **(новое)** | — | R, свои | — | — |
| Смотреть сообщение — `GET /reports/<id>` **(новое)** | — | R, своё | — | — |
| Смотреть и фильтровать очередь сообщений — `GET /reports/queue` **(новое)** | — | — | R, все | — |
| Разобрать сообщение — `POST /reports/<id>/review` **(новое)** | — | — | W, все | — |
| Проверить состояние сервиса и БД — `GET /health` | R | R | R | R |

`GET /health` — общедоступная техническая проверка состояния контейнера и доступности БД, без данных района. При ошибке БД возвращает 503. Приём сообщений `city.logs.>` и `city.events.grid.alarm.>` идёт через Транспорт внутри сети `city`, не через пользовательский HTTP-маршрут. Создание тревоги и запись журналов выполняются сервисом автоматически. Общие маршруты входа и выхода предоставляет `citykit`.

## Новые функции: четыре вопроса

### 1. Создать сообщение — `POST /reports`

1. **Кто вызывает:** пользователь с ролью `житель`; роль проверяется до кода функции.
2. **Чьи данные:** создаётся только собственная запись. `owner_sub` сервер берёт из `current_user()["sub"]`.
3. **Поля:** принимаются только `category` из трёх значений (`suspicious_login`, `fraud`, `other`) и `summary` длиной 10–200 символов. Присланные `owner_sub`, `status`, `reviewer_sub` игнорируются; статус новой записи задаёт БД. Ответ перенаправляет на страницу созданной записи.
4. **Журнал:** `soc.report.created`, номер сообщения, пользователь из сессии, время и результат. Текст `summary` и тело запроса в журнал не попадают.

### 2. Список своих сообщений — `GET /reports`

1. **Кто вызывает:** только роль `житель`.
2. **Чьи данные:** только свои: выборка всегда содержит `WHERE owner_sub = ?`, значение берётся из сессии даже при включённом фильтре.
3. **Поля:** необязательный `status` допускает `new`, `reviewed`, `dismissed` или пустое значение; другой статус даёт 400. Список возвращает номер, категорию, статус и время, без описания и служебных полей.
4. **Журнал:** отдельное событие успешного чтения списка не создаётся. При отказе по роли общий обработчик пишет `access.denied` с путём и требуемой ролью; содержимое списка не пишется.

### 3. Просмотр своего сообщения — `GET /reports/<id>`

1. **Кто вызывает:** только роль `житель`.
2. **Чьи данные:** только запись, где одновременно совпали `id` и `owner_sub` с идентификатором из сессии. Чужой и отсутствующий номер дают одинаковый 404.
3. **Поля:** вход — только целочисленный `id` из адреса; ответ — категория, статус и описание собственной записи. Служебные поля владельца и аналитика не отдаются.
4. **Журнал:** `soc.report.viewed` с номером записи при успехе; `access.denied` с номером при отказе. Без содержания сообщения.

### 4. Очередь аналитика — `GET /reports/queue`

1. **Кто вызывает:** только роль `аналитик_soc`.
2. **Чьи данные:** сообщения всех жителей в пределах служебной роли; выдаётся не более 100 последних записей.
3. **Поля:** необязательный `status` допускает только `new`, `reviewed`, `dismissed` или пустое значение; неверный статус даёт 400. Ответ показывает номер, категорию, описание, статус и время, без `owner_sub`.
4. **Журнал:** отдельное событие успешного чтения очереди не создаётся. При отказе по роли общий обработчик пишет `access.denied` с путём и требуемой ролью.

### 5. Разобрать сообщение — `POST /reports/<id>/review`

1. **Кто вызывает:** только роль `аналитик_soc`; роль проверяется до поиска записи.
2. **Чьи данные:** допускается сообщение любого жителя со статусом `new`. Отсутствующий или уже обработанный номер даёт 404.
3. **Поля:** из формы принимается только `decision` со значением `reviewed` либо `dismissed` и целочисленный `id` из адреса. `reviewer_sub` и время выставляет сервер; остальные поля формы игнорируются. Ответ перенаправляет в очередь.
4. **Журнал:** `soc.report.reviewed`, номер сообщения и решение; пользователь и время добавляются общим журналом. Содержание сообщения, тело запроса и токены не пишутся.

Все меняющие запросы требуют CSRF-токен. Код функций: `app/__init__.py`; HTML: `app/templates/reports.html`, `report_detail.html`, `report_queue.html`. Проверки: `tests/test_reports.py`.

## Проверки

| Функция | Разрешённый случай | Чужой объект | Неверная роль |
| --- | --- | --- | --- |
| Создание и список | Житель создаёт запись; подставленный `owner_sub` игнорируется, ответ 200 после перехода; фильтр по статусу показывает только свои записи | Другой житель не видит запись и получает 404 на её адресе | Аналитик получает 403 на `POST /reports` |
| Просмотр записи | Владелец получает 200 | Другой житель получает 404 | Аналитик получает 403 |
| Разбор | Аналитик меняет статус, очередь возвращает 200 | Неизвестный номер даёт 404 | Житель получает 403 до поиска номера |
